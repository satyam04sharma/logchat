# Versioned compact embedding projection

The first bounded implementation adds `compact-evidence-v2`, with the unchanged full durable evidence schema. Its semantic input omits only important-field reference bookkeeping. Historical v1 rendering remains byte-for-byte compatible. The model digest, document/query prefixes, compression policy, pattern formula and canonical replay identity remain unchanged. No indexed payload or vector is migrated.

Synthetic regressions cover frozen v1 embedding bytes, all JSON value types (including integer versus float and boolean), original ID aliases and Unicode correlations, complete durable bindings, unknown-version rejection, invalid bindings, newly generated v2 chunks, and mixed v1/v2 prepared-payload round trips with an unchanged embedding spec. These are mocked embedding checks, not real-provider completion evidence.

Preserved pilot validation runs read-only, renders all 16 failed-job chunks in memory and compares v1 bytes with the historical recipe. The temporary v2 representation changes only evidence version and the derived chunk ID, and its projection preserves typed keys/values, summary and metrics exactly. It also checks the 28 published v1 chunks remain renderable. Content-free reports and validation logs use the portable evidence location `projection-checks/iteration-1/` in the external review evidence bundle. Source evidence, credentials and vectors are not copied into public documentation.

Measured pilot projection maximums were 3,472 characters for v1 and 2,075 for v2, before the provider prefix. The preserved database file remained byte-for-byte unchanged. Focused checks passed (51 tests, 34 subtests); the full suite passed (751 tests, one skipped, 184 subtests, two existing Typer/Click deprecation warnings). Native renderer contracts, isolated sdist/wheel build, distribution structure audit, candidate-byte wheel audit (71 runtime files) and whitespace checks passed. No background services were started; test/build processes completed. Evidence includes `pilot-projection-report.json`, `pytest.log`, `build.log` and `validation.json` under the portable location above.

The second bounded implementation adds terminal provider context diagnostics. Only HTTP 400 from `POST /api/embed`, with a JSON `error` exactly matching either recognized Ollama overflow message, becomes `embedding_input_context_exceeded`. Error responses are bounded to 1,024 bytes. The public exception and persisted category contain only the fixed category; unrelated errors, malformed responses, oversized error bodies and invalid vectors retain the conservative generic failure. The worker marks recognized overflow non-retryable, retaining prepared work for explicit retry after a fix.

Synthetic transport and real-SQLite worker regressions verify complete input and `truncate:false`, precise recognition, generic handling of unrelated HTTP 400/500 and malformed responses, zero publication when the second vector request fails, terminal failure surviving restart, and normal atomic completion after explicit retry. These checks do not call a real model. Overflow messages follow the [Ollama embedding handler](https://github.com/ollama/ollama/blob/main/server/routes.go); classification deliberately avoids substring matching against arbitrary provider prose.

Iteration-two validation passed: 33 focused tests and nine subtests; 765 full-suite tests and 184 subtests, with one skipped and two existing Typer/Click deprecation warnings; native renderer contracts; isolated sdist/wheel build; distribution structure and 71-file candidate-byte audits; and whitespace checks. No background services were started, and all test/build processes completed.

The third bounded implementation adds leased explicit failed-job transport recovery. The existing authenticated, bounded project retry marks only failed jobs as eligible; ordinary retries and new work do not authorize rewriting. Under the normal lease and refinement transaction, each v1 chunk upgrades to v2 with its full-evidence-derived chunk ID. Independently validated typed canonical JSON must otherwise match exactly, including the batch envelope, one-to-one ordered membership, patterns, catalog, bindings, values, metrics, model prose, metadata, uncertainties and loss notes. Initial payload hashes and canonical key/digest ledgers remain immutable. The worker uses the returned durable job for normal embedding and atomic completion. Stale in-memory payloads and expired, unleased or completed jobs cannot refine or publish. Restart retains the upgraded payload; replay of the initial intake retains its original identity.

Synthetic real-SQLite recovery tests cover explicit authorization, typed mutations, crash/reclaim fencing, restart/idempotence, immutable ledgers, completed-work rejection and the normal worker publishing only returned upgraded chunks with generation forbidden. Actual disposable-copy recovery to 1200 indexed events and 44 real vectors remains required work for the next iteration. These three bounded iterations make no actual embedding or generation calls and make no universal model-fit claim. Exact tokenizer preflight remains deferred; the provider still receives complete inputs with `truncate:false`.

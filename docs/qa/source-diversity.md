# Bounded context across repeated multi-service incidents

The 100K workload contains four observations of the correlated incident in each of web, worker and auth. Previously all services shared one environment/period cell, and the first six ranked candidates could be four web plus two worker observations. Auth support was unavailable to the relevance model even when all twelve matching chunks had been retrieved. The one-observation-per-service pilot did not expose this concentration.

Candidate admission now preserves requested-ID support ahead of unrelated neighbors, then interleaves services and sources within each service under the existing retrieval cap. After retained-field literal eligibility, remapping applies the same bounded service/source fairness before its existing six-candidate cap. Original scopes, immutable candidates and ranking scores are preserved; fair admission is recorded in stage provenance.

Explicit whole known service labels in the question add a relevance-model contract: prioritize one relevant observation per requested service before repeated observations. The model still controls selections, with strict reference membership, confidence and unchanged three-per-cell/eight-total bounds. No service receives fabricated or automatically promoted evidence. Model rejection, low confidence, unavailable literal support and insufficient selection/input budgets retain honest partial/empty context and explicit coverage gaps. Requested, eligible, selected and missing known services are recorded in remapper provenance. A wholly unavailable unknown service name is not inferred from an arbitrary vocabulary; source coverage gaps and the actual selected subset remain visible.

The structural regression fixture contains twelve individually validated compact chunks (four per service) plus twelve higher-ranked unrelated vector/lexical neighbors. Under unchanged limits it retrieves four matching chunks per service, supplies two per service and permits a mock relevance selector to choose one per service. Additional checks cover many web sources, atomic case-insensitive service names, absent identifiers, irrelevant/unavailable services, model rejection/outage, low confidence and insufficient budgets. These tests verify transport and validation contracts, not production model quality. Real-model pilot and fresh 100K acceptance must still demonstrate actual three-service selection, source precision, citations, corpus accounting and restart/replay. Finite selected recall remains intentional; selecting all twelve observations is not required.

A follow-up corrects multi-field cap starvation: partial matches for only one requested value can no longer consume all retrieval slots ahead of a record that satisfies every requested field. The retriever first collects the same bounded validated backend pools for every cell, then shares the remapper's pure anchor/record eligibility rule across that complete pool. Alternatives in one field remain OR; distinct fields must match within the same source record. Shared anchors also preserve comparisons spanning environments or periods.

Before both retrieval and remapping caps, deterministic admission reserves actual eligible witnesses for same-field alternatives and explicitly requested known services, then admits fair repetitions. A late second alternative stays visible instead of becoming an absent-value AND constraint when anchors are recomputed. If actual witness requirements exceed existing caps, explicit cap gaps remain; limits are not increased. This does not bypass model relevance, confidence, scope, citation or prompt-budget validation. Malformed retained candidates remain isolated to their failed cell. Structural regressions include the 12-partial-plus-13th-joint record case, late alternatives under both caps, cross-cell comparisons and values split across different records.
